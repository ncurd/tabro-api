# 签到积分入口

启用 Auth 统一计费后，顶部积分区域和账户菜单会读取 Auth 账户摘要中的 `daily_check_in`。活动开放且当天未领取时，展示「签到领积分」、奖励范围和领取后的有效天数；已领取时展示当日奖励及到期日期。关闭活动、身份不匹配或摘要缺失时不显示领取引导。

入口在新标签页打开 Auth 的 `DailyCheckIn` 页面，带上经过身份匹配的 `TenantId` 与 `ExpectedSubject`。Auth 再校验会话并通过自己的防伪表单发放积分。API 的本地访问令牌不会转发到 Auth。用户返回 API 页面后，现有窗口焦点刷新会更新余额和签到状态。

签到默认有效期为 30 天，个人和企业规则分别在 Auth 管理后台配置。企业奖励进入企业账户并分配给领取人。每批到期时间由 Auth 固定，到期后不再计入 API 展示的可用积分，也不能继续消费；客户端不自行累加奖励或估算余额。

部署顺序：先执行 Auth 的 `DailyCheckInExpiry` 数据库迁移并发布 Auth，再发布 API 后端与前端。旧 Auth 摘要不含该字段时，现有积分展示仍可使用。详细配置和迁移命令见 tabro-auth 仓库的 `docs/DAILY_CHECK_IN_CN.md`。
